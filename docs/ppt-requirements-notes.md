# PPT 1–25页功能与实施边界审计

本次逐页读取PPT前25页，共登记 209 项功能/入口：计划实现 57 项、仅按钮入口 152 项；这些是设计范围计数，不是已完成声明。另有39项数据目录，完整列在requirements_audit.json。

## 必须保留的目录

- 三大域：数据清洗集成、知识抽取与图谱、业务协同工作流。
- 12个业务节点：数据准备、静态地质研究、动态分析、异常诊断、方案编制、多方案比选、专业审核、综合审定、任务下达、执行跟踪、效果评估、知识沉淀。
- 数据资源／规范／联合质控／服务四层，业务标签三级，单井—井组—区块三级导航。
- 权限四元组、对象级继承、节点权限扩展回收、会签委托等均为按钮入口，不能用角色切换器冒充真实鉴权。
- 8项联动规则、L0—L3质控分级、4类知识接口、4个节点知识推送均须可找到。仅指定DAG计算链路与异常历史推送工作，其余显示“规划入口”。

## PPT内部不一致

第11页写44小类，但第12页实际枚举 G9+P8+M9+T3+W5+K5=39项，缺少5项明细。第11页类别含“示功图”，第12页的六类改为含“井组/区块关联”；不可默认为同一分类。推荐界面显示“PPT标称44｜已列明39”，而不是伪造44个可用数据源。M-6原文“其他冬天监测数据”，可显示“其他动态监测数据”，同时保留原文校订说明。

## 用户限定的真实功能

1. IF异常识别＋GRIN缺失补全＋已具备字段的油藏规则联合质控。SCADA、A2、专业软件注入、完整跨专业实验互证仅按钮。
2. UIE本体约束抽取、实体对齐、RotatE关系候选、时序关联、图谱可视化与业务语义检索。没有官方预训练权重时必须标明“轻量结构复现”；不得以正则假称UIE。
3. 以井唯一编码串联单井、井层、井组，加入CRM响应和地质约束。公开资料缺少真实井组与小层、断层几何，生成映射必须标“演示假设”，统计关联不等于水力连通。
4. DFN／EDFM与DAG计算链路。若只做2D简化或单相，则界面必须明确；不能把几何动画当作多相求解结果。
5. Anomaly Transformer生产异常候选、机理校验、历史模式；Arps只在稳定制度、适用分段拟合。真实异常不清洗平滑，正常递减不等于异常。
6. 每个模型页需显示训练／验证／测试的数量、比例、样例和实际指标，标明指标来自真实标签、遮蔽观测、受控注入还是生成算例。

## 来源数据缺口与展示限制

- 当前公开压力字段单位未确认，不可自动标MPa；注采体积是地面标准体积，缺PVT/含水层等信息时不可确诊地下能量或注采失衡。
- FORCE GROUP表示地层群，不能当开发井组。SPE9 I/P是模拟控制组，不能当真实地理井组。不同来源井ID要保持命名空间。
- 历史异常只有规则候选而无专家根因／处置效果标签，检索显示候选模式与证据，不补造“已成功治理”的案例。
- 中文UIE语料来自真实表格生成的模板摘要，不是原始地质报告；评价只能说明此类语料上的抽取能力。
- DFN公开几何缺校准裂缝开度、渗透率、应力等；补充生成物性仅用于公开演示算例。
- 油藏机理模拟参数、数据来源和“真实训练／轻量复现／预计算重放／交互求解”运行方式应逐模块明示。
